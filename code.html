Inside Base.for

STOCHEM is a single fixed-form Fortran 77 program of ~13,300 lines, plus an INCLUDE file (INOPERVM10.SOA2) holding the grid dimensions, species list and file paths. Everything on the model page — advection, mixing, chemistry, emissions — maps onto named subroutines. Line numbers below refer to the current build.

One timestep through the code

The main program (PROGRAM STOCHEM, line 2) runs an outer loop over 3-hourly advection steps (ASTEP=10800, line 370). Each pass reads met, loops over all 50,048 parcels, then does cell-level book-keeping:

READPP2 / METREA2read 6-hourly winds, T, q, cloud, BL depth
→
RKO4 + VELOCRK4 advection + stochastic diffusion per parcel
→
JVALS + DJCALCphotolysis rates at 4 points in the step
→
EGET / DDCALC / DWCALCemissions, dry & wet deposition
→
DERIV + CHEMCOCRI chemistry — the expensive call
→
STORE / PLOT / CLMIXemission buffers, Eulerian remap, cloud mixing

Where everything lives

PhaseSubroutine (line)What it does
Setup GETLIS (11517) · INIGRI (1866) · INIPOS (1912) · AINDEX (11460) Reads the flux/species lists, builds the two met grids, seeds 50,048 parcels on the eta grid and indexes each to its analysis cell.
Initial state INICON (1610) · RESTART Cold start from a zonally-symmetric July climatology, or warm start restoring the full parcel state from RESTART.BIN.
Meteorology READPP2 (872) · METREA2 (1220) · WATREA2 (1450) · CLRAIN2 (1306) · BLREAD2 (1381) · BOUND (~15096) Ingests winds, temperature, humidity, cloud base/top/cover and precipitation; diagnoses boundary-layer depth by two methods and keeps the deeper.
Advection RKO4 (2231) · VELOC (2500) · INTERP · REPOS (2437) 4th-order Runge–Kutta along the interpolated 3-D wind, with careful pole handling. VELOC adds the stochastic diffusion kick.
Chemistry JVALS (11919) · PHOT (12079) · DJCALC (2694) · DERIV (2733) · CHEMCO (7776) · EQMCON (9813) Photolysis-rate table (~1,000-line PHOT block), then DERIV — a ~5,000-line right-hand-side for all ~700 CRI reactions — with rate constants set in CHEMCO.
Emissions EMREAD (10438) · EMCALC (10617) · EMUPDT (11128) · EGET (2607) · STORE (11061) · LIGHTREAD · STRATCALC Monthly surface/aircraft/lightning inventories (DONO2 gates ACNOXmm.OUT/LNOXmm.OUT), injected into whatever parcels sit in the emitting cell.
Deposition DDCALC (11003) · DWCALC (10834) Land/sea dry-deposition velocities; scavenging by dynamic (ADP) and convective (ACP) rain.
Mixing VELOC (2500) · CLMIX (14994) Continuous stochastic diffusion via random wind kicks, plus the convective cloud-column homogenisation shown below.
Output PLOT (9863) · SMOOTH (9944) · MCALC (10027) · STATS/CALSTA/OUTSTA · OUTBUD (10157) · OUTLEV (10110) Bins parcels onto the 72×36×9 grid, writes stoch3d.dat/.bud/.tot/.sta, and periodically dumps DUMP.BIN for restarts.
Diagnostics CELLBAL (11643) · INITBAL (11827) · ZEROFL (11421) Optional single-cell NOx/O3 budget tracking — a parcel is followed and every flux in/out of its cell is logged.

The stochastic bit, verbatim

This is the actual entrainment decision in CLMIX — the loop the convection schematic illustrates. FRAC is derived from convective precipitation (or 4× cloud cover for non-raining cloud); every entrained parcel is then overwritten with the cell's cloudy-mean composition: 

          R=RANDNUM(SEED3)
          IF(R.LT.FRAC(I,J)) THEN
            LCLOUD(K)=.TRUE.
            II=INT((I-1)*DLONGM/DLONG)+1
            JJ=INT((J-1)*DLATM/DLAT)+1
            NCLOUD(II,JJ)=NCLOUD(II,JJ)+1
            DO N=1,NC
              CLCONC(N,II,JJ)=CLCONC(N,II,JJ)+XX(N,K)
            ENDDO
          ENDIF

And the continuous turbulent diffusion in VELOC — a Gaussian kick S·√(2K/Δt) added to the analysed wind (HDIFF=5300 m² s⁻¹ horizontally, VDIFF=7×10⁻⁹ vertically, switched off near the poles): 

        V(1)=(U7+S(1)*(2.0*(1.0/ASTEP)*HDIFF)**0.5)*
     &                DPMY/COS((POS(2)-90.0)*RAD)
        V(2)=-(V7+S(2)*(2.0*(1.0/ASTEP)*HDIFF)**0.5)*DPMY
        V(3)=W7+S(3)*(2.0*(1.0/ASTEP)*VDIFF)**0.5

So you want to change something

Add a species

Positional bookkeeping: bump NC, add to CNAMES/CLIST, seed it in INICON, add production/loss terms in DERIV, give it an emissions channel (EMREAD→EGET) and deposition velocities. The index order is the mechanism-file order — misalign it and every downstream flux is silently wrong.

Add a reaction

One row in CHEMCO's RC(JB,n) table, bump NR, then the production/loss terms in DERIV. To output its flux, flag it in flux10_OH.dat (and make sure NUM3DFLUX in the include file is large enough).

Base_omp.for — the OpenMP build

The parcel loop is the parallel region: parcels are processed in blocks (the nblock/JA loop ending at line ~632), with per-thread PRIVATE state for concentrations and LASTPRIVATE/ATOMIC handling for shared diagnostics like the SOA pools and accumulated fluxes. Serial runs take ~45 h per model year; the OpenMP build brings that to ~3–8 h on 24 threads.

Line numbers refer to the current Base.for build and will drift as the file is edited — grep for the subroutine name rather than trusting the number. The runtime contract is simple: four stdin answers (year, month, day, run length in days); a RESTART.BIN present in the run directory means a warm start and the typed date is ignored.
